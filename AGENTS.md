# AGENTS.md

## Working rules

1. State assumptions before implementation when requirements are ambiguous.
2. Prefer the smallest implementation that satisfies the brief.
3. Keep changes surgical; do not refactor unrelated starter code.
4. Tie each change to a verifiable acceptance criterion.
5. Preserve progressive enhancement, keyboard access, visible focus states, and reduced-motion support.
6. Update `PROGRESS.md` when a milestone is completed or a decision changes.
